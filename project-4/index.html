Overview

From separate frames
to a shared canvas.

Each sequence was photographed from an approximately fixed center of projection while rotating the camera. A homography is therefore a useful model for registering these views.

I implemented correspondence collection, least-squares homography recovery, forward and inverse warping, two interpolation methods, and center-weighted feathering without high-level warping functions.

Projective model

p′ ∼ Hp

With H33 fixed to 1, a homography has eight unknowns. Each pair contributes one equation for u and one for v.

[ x y 1 0 0 0 −ux −uy ] h = u [ 0 0 0 x y 1 −vx −vy ] h = v
computeH.pyLeast squares
def computeH(src_pts, dst_pts):
    A_rows, b_values = [], []

    for (x, y), (u, v) in zip(src_pts, dst_pts):
        A_rows += [
            [x, y, 1, 0, 0, 0, -u*x, -u*y],
            [0, 0, 0, x, y, 1, -v*x, -v*y],
        ]
        b_values += [u, v]

    A = np.array(A_rows, dtype=np.float64)
    b = np.array(b_values, dtype=np.float64)
    h, _, rank, _ = np.linalg.lstsq(A, b, rcond=None)

    if rank < 8:
        raise ValueError("The correspondence system has rank below 8.")

    return np.array([
        [h[0], h[1], h[2]],
        [h[3], h[4], h[5]],
        [h[6], h[7], 1.0],
    ])

Part A.3 / Warp the images

Why forward warping
leaves holes.

I first implemented forward warping to expose its failure mode. The homography maps every source pixel to a continuous destination coordinate, but an image array only has integer row and column indices. Rounding those coordinates does not guarantee that every destination pixel receives a value.

Forward mapping

p′ = Hp

For a source pixel p = (x, y, 1), multiplication produces the homogeneous vector (ũ, ṽ, w̃). Dividing by w̃ gives the Cartesian destination (ũ/w̃, ṽ/w̃), which is usually fractional. For example, (1842.37, 916.64). To index the output array I have to round it to (1842, 917).

Why pixels disappear

A projective warp can expand the image. Two adjacent source pixels may land more than one output pixel apart, so no source coordinate rounds into the cells between them. Other source pixels can round to the same destination and overwrite one another. Forward mapping therefore creates both gaps and collisions.

Nearest-neighbor and bilinear interpolation do not repair this traversal: they describe how to sample a source location, but forward warping never asks about destinations that were skipped.

The solution

Reverse the question.

p = H−1p′

Inverse warping iterates over every integer output pixel p′, so holes cannot be skipped. H−1 maps that destination back to a fractional source position p. If p lies inside the source image, I use nearest-neighbor or bilinear interpolation to decide its color; if it lies outside, the mask remains false.

Two samplers

One coordinate,
two ways to sample.

An inverse-mapped location is usually fractional. For example, (421.38, 117.72). Nearest neighbor snaps that location to one source pixel. As the fractional coordinate moves, the chosen pixel stays constant and then jumps, turning a straight edge into a staircase. Bilinear interpolation changes continuously because it blends the four surrounding pixels according to distance.

Part A.4 / Blend images into a mosaic

Build the canvas,
then blend.

A mosaic is not assembled by simply placing photographs next to one another. Every output pixel belongs to a shared coordinate system. I first determine that system’s bounds, then ask where each output pixel came from in every source image, and finally combine the valid answers.

01

Find one shared canvas

Transform the four corners of every photograph into the reference frame. The smallest and largest transformed x and y values define the full panorama bounds.

02

Translate into array coordinates

Some transformed corners are negative. A translation T shifts the global minimum to (0, 0), so every panorama coordinate has a valid non-negative array index.

03

Visit every output pixel

For each pixel on the canvas, apply the inverse of T H. After dividing by the homogeneous w coordinate, this gives the floating-point location to sample in the source image.

04

Keep only valid samples

A source contributes only if the four bilinear neighbors fall inside its width and height. That same condition creates a boolean mask used later during blending.

mosaic.py1 · Shared bounds
transformed_corner_sets = []

Center-to-edge feathering

Use the masks, then trust the center of each frame most.

A hard overwrite would create a visible seam wherever exposure or alignment differs. Instead, each original image gets a weight map: the weight is strongest near its center and decreases toward every edge. I warp this weight map with the same homography as its image.

The validity mask then zeros weights outside the warped photograph. In an overlap, colors are multiplied by their warped weights, summed, and divided by the total weight. A pixel covered by only one image is copied from that image; a pixel covered by several becomes a smooth, spatially varying average.

Imosaic = Σ wiIi / Σ wi

mosaic.py5 · Feathered compositing
# Linear distance to the nearest source-image edge.
x_distance = np.minimum(x, width - 1 - x)
y_distance = np.minimum(y, height - 1 - y)
source_weight = np.minimum(y_distance[:, None], x_distance[None, :])
source_weight = source_weight / source_weight.max()

# Warp weights just like image colors, then remove invalid regions.
w_left  = warped_weight_left  * mask_left
w_ref   = warped_weight_ref   * mask_ref
w_right = warped_weight_right * mask_right

total_weight = w_left + w_ref + w_right
valid = total_weight > 0

mosaic[valid] = (
    warped_left[valid]  * w_left[valid, None]
  + warped_ref[valid]   * w_ref[valid, None]
  + warped_right[valid] * w_right[valid, None]
) / total_weight[valid, None]
