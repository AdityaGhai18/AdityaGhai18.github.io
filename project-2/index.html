Part 1.1

Convolutions from Scratch!

A convolution takes a small kernel, flips it, and slides it across an image. At each position, the kernel and image values are multiplied and summed to produce one pixel in a new feature map.

Dx[1, 0, −1]

Dy[1, 0, −1]T

These finite difference filters approximate brightness changes: Dx across the horizontal direction and Dy across the vertical direction.

Implementation

Convolution with NumPy

Four-loop version Python 
def conv(image, kernel):
  kernel = np.flip(kernel)

  height, width = image.shape
  kernel_height, kernel_width = kernel.shape

  pad_height = kernel_height // 2
  pad_width = kernel_width // 2

  padded = np.pad(
    image,
    ((pad_height, pad_height),
     (pad_width, pad_width)),
    mode="constant",
  )

  output = np.zeros((height, width))

  for row in range(height):
    for col in range(width):
      total = 0

      for kernel_row in range(kernel_height):
        for kernel_col in range(kernel_width):
          im_value = padded[
            row + kernel_row,
            col + kernel_col,
          ]
          kernel_value = kernel[
            kernel_row,
            kernel_col,
          ]
          total += im_value * kernel_value

      output[row, col] = total

  return output
Two-loop version Python 
def conv_two_loops(image, kernel):
  kernel = np.flip(kernel)

  height, width = image.shape
  kernel_height, kernel_width = kernel.shape

  pad_height = kernel_height // 2
  pad_width = kernel_width // 2

  padded = np.pad(
    image,
    ((pad_height, pad_height),
     (pad_width, pad_width)),
    mode="constant",
  )

  output = np.zeros((height, width))

  for row in range(height):
    for col in range(width):
      patch = padded[
        row : row + kernel_height,
        col : col + kernel_width,
      ]

      output[row, col] = np.sum(
        patch * kernel
      )

  return output
01
Input and kernel flip

Both functions take an image as a NumPy array and a kernel to apply. The kernel is flipped first because mathematical convolution uses the reversed kernel rather than applying it in its original orientation.

02
Dimensions and padding

After reading the image and kernel dimensions, the padding on each side is set to kernel_size // 2. For the odd-sized kernels used here, this places the kernel center over every image pixel and keeps the output the same height and width as the input. Without padding, the border would remove output positions; adding those pixels back means that every input position produces one output pixel.

03
The four-loop scan

The outer row and column loops scan across the image. At each location, the inner two loops scan across the kernel, multiply each padded image value by its corresponding kernel value, and add the product to a running total. That total is then written to the matching position in the output image.

04
The two-loop version

The outer image scan stays the same, but the inner kernel loops are replaced by one NumPy slice. This extracts the complete image patch beneath the kernel, and np.sum(patch * kernel) performs all of the multiplications and accumulation at once.

Performance

Runtime and boundary handling

For an H × W image and a Kh × Kw kernel, the runtime is O(HWKhKw) because every kernel value is used at every image position. When the kernel size is fixed, an n × n image therefore takes O(n2) time: doubling both image dimensions creates roughly four times as many positions to process. The two-loop version has the same asymptotic runtime, but is faster in practice because NumPy performs the inner calculation in optimized compiled code; scipy.signal.convolve2d is generally faster still for the same reason.

Boundary handling: our zero padding is equivalent to using mode="same", boundary="fill", and fillvalue=0 with scipy.signal.convolve2d.

Correctness

Checking against SciPy

I applied scipy.signal.convolve2d to the same grayscale image with both Dx and Dy. Using np.allclose verifies that my implementation and SciPy produce matching values within a small floating-point tolerance.

Part 1.2

Finite Difference Operator

I convolved the cameraman image with Dx and Dy to measure horizontal and vertical intensity changes. Together, the two partial derivatives describe the strength of an edge at each pixel.

Gradient magnitudeG = √(Gₓ² + Gᵧ²)

Binary edge mapedge = G > 100

The magnitude combines both directions into one edge-strength image. I normalized this magnitude only for display, then applied a threshold of 100 to the original magnitude values to produce the binary edge map. Below 100, weak changes in textured regions remained as fine, grainy noise that distracted from the main contours. Going above 100 removed more of that noise, but also began erasing real, lower-contrast edges. I therefore chose 100 as the best compromise between a clean image and preserving the important structure.

Part 1.3

Derivative of Gaussian (DoG) Filter

The finite difference operator responds to real edges, but also amplifies small pixel changes and noise. A Gaussian filter reduces those high-frequency variations before the derivatives are taken.

Gaussian construction Python

01

cv2.getGaussianKernel creates a 7-element 1D Gaussian with σ = 1.5. Taking its outer product with its transpose produces a symmetric 7 × 7 filter whose weights are largest at the center and decrease smoothly outward.

02

Convolving that Gaussian with Dx and Dy creates the two DoG filters. Each filter performs smoothing and differentiation together in one convolution.

03

A convolution can be represented as multiplication by a convolution matrix. Because matrix multiplication is associative, the operations can be regrouped without changing the result: (I ∗ G) ∗ Dx = I ∗ (G ∗ Dx) = I ∗ DoGx (I ∗ G) ∗ Dy = I ∗ (G ∗ Dy) = I ∗ DoGy

Comparison

Smoothing before differentiation

What changed? Gaussian smoothing suppresses the small intensity fluctuations that the plain finite difference filters interpret as edges. The important outlines become more stable and continuous, allowing a lower threshold of 40 without bringing back the same level of noise.

Verification. Writing each convolution as a matrix operation makes the equivalence explicit. Matrix multiplication is associative, so the Gaussian and derivative matrices can be multiplied first and then applied to the image: (I ∗ G) ∗ Dx = I ∗ (G ∗ Dx) (I ∗ G) ∗ Dy = I ∗ (G ∗ Dy) The saved two-step and DoG results are therefore identical: the right-hand side simply precomputes each DoG filter before the single image convolution.

Part 2.1

Image “Sharpening”

A Gaussian blur is a low-pass filter: it keeps gradual intensity changes while removing fine detail. Subtracting that blurred image from the original isolates the high frequencies, which primarily contain edges and small texture changes. Here, I denotes the original image and G ∗ I denotes the Gaussian-blurred image.

Low frequenciesL = G ∗ I

High frequenciesH = I − L

Sharpened imageIsharp = I + αH

Expanded formIsharp = (1 + α)I − α(G ∗ I)

Unsharp maskU = (1 + α)δ − αG

The parameter α controls how much high-frequency detail is added: larger values create a stronger effect, but can also exaggerate noise and produce halos around edges. Intuitively, sharpening does not create new detail; it increases local contrast around details and edges that were already present in the original image. Here, δ is the identity filter, so convolving with U performs the original-image and blurred-image combination in one operation.

Part 2.2

Hybrid Images

A hybrid image combines the low frequencies of one image with the high frequencies of another. Up close, the eye can resolve the high-frequency edges; from farther away, those details disappear and the low-frequency structure becomes dominant.

Low componentL = G ∗ Ino glasses

High componentH = Iglasses − G ∗ Iglasses

Hybridclip(L + 3H, 0, 255)

I used a Gaussian with σ = 20 and weighted the high-frequency component by 3. Both inputs were converted to grayscale. Before filtering, I resized them to the same dimensions and translated the glasses image downward by 120 pixels so the eyes, face, and glasses aligned with the no-glasses image.

Parameter experiments

Finding a useful balance

I adjusted both the Gaussian standard deviation, σ, and the multiplier on the high-frequency component. A larger σ produces a wider Gaussian and therefore a stronger blur. Subtracting that blur from the glasses image leaves a broader, more visible detail component. The multiplier then controls how strongly that detail is added to the low-frequency image.

The selected result above uses σ = 20 and a high-frequency weight of 3. This stronger detail is necessary for the glasses to remain visible in Close View while still fading in Far View.

Parts 2.3 + 2.4

Gaussian and Laplacian Stacks + Multiresolution Blending

A Gaussian stack stores progressively smoother versions of an image without downsampling, so every level keeps the original dimensions. A Laplacian stack subtracts adjacent Gaussian levels to separate the image into frequency bands. Adding every Laplacian level, including the final low-frequency residual, reconstructs the original image.

Building both stacksPython
def gaussian_stack(image, num_levels=5, mult=1):
    stack = [image.astype(float)]

    for level in range(num_levels - 1):
        sigma = mult * (2 ** level)
        ksize = 2 * int(np.ceil(3 * sigma)) + 1
        g1d = cv2.getGaussianKernel(ksize, sigma)
        gaussian = g1d @ g1d.T
        stack.append(blur_image(stack[-1], gaussian))

    return stack


def laplacian_stack(gaussian_levels):
    stack = []

    for level in range(len(gaussian_levels) - 1):
        stack.append(
            gaussian_levels[level]
            - gaussian_levels[level + 1]
        )

    stack.append(gaussian_levels[-1])
    return stack
